# 租房信息检查

Go + TypeScript 的最小 Web 应用：上传填写好的 Excel，查看识别的房源与费用信息，再调用分析接口。

目前支持文件选择、拖放上传、动态字段预览、重复项目提示和模板下载。**真实 Agent、判断 skill 和数据库暂未接入**。点击“开始检查”会显示分析暂未开放，不会生成模拟风险判断。

## 启动应用

需要 Go 1.25+、Node.js 22.12+。在仓库根目录执行：

```sh
npm --prefix web ci
npm --prefix web run build
go run ./cmd/server
```

打开 <http://127.0.0.1:8080>。Go 同时提供 API 与构建后的前端，不需要另装 Web 服务器。

开发时，两个终端分别运行：

```sh
# 终端一：后端
go run ./cmd/server

# 终端二：前端热更新
npm --prefix web run dev
```

打开 <http://127.0.0.1:5173>，开发服务器把 `/api` 请求代理到 Go 的 8080 端口。服务默认只监听本机，可通过 `-addr`、`-web-dir`、`-template` 参数调整地址、前端目录和模板文件。

## 表格格式

- 一个文件对应一套房源，使用一张有内容的工作表；额外的空工作表允许保留。
- A 列是项目名，B 列是填写内容。首行可用“项目 / 数值”等表头，也兼容现有模板 A1 为空、B1 为“数值”的形式。
- 项目名称、数量及顺序可以变化。新增、删除、改名、重排不需要修改 Go 结构体或 TypeScript 类型。
- 有名称但未填写的项目保留为 `null`；数字零保留为文本 `"0"`，不是空白。
- 重复名称按原来的顺序分别保留，并显示核对提示。字段保留工作表和单元格位置。
- 金额、单位、押付方式、备注按 Excel 显示文本保留，不猜测、不自动转换金额。原文中的换行也会保留。
- 公式需要先确认结果并粘贴为数值；当前不会重算公式，也不会把可能过期的缓存结果当作有效数据。
- 合并单元格、多张有内容的工作表、B 列之后还有数据、只有值没有项目名称时，明确提示整理格式，不静默丢弃内容。

上传限制：`.xlsx`、最大 10 MB、最多 10 张工作表、每张最多 2000 行、最多 500 个项目。解压总量限制为 32 MB；字段名最多 256 字符，填写值最多 10000 字符。布局改变需要扩展解析规则，单纯增减项目无需改代码。

## 数据协议与后续扩展

业务项目存放在动态数组 `fields` 中。Go 的 `document.Field` 和 TypeScript 的 `RentalField` 只描述一个通用字段，不为房租、停车费等分别声明属性。

以下是示意数据，上传后会使用实际内容：

```json
{
  "schemaVersion": 1,
  "fileName": "房源.xlsx",
  "fields": [
    { "id": "field-1", "label": "月租", "value": "2800元/月", "sheet": "Sheet1", "cell": "B2" },
    { "id": "field-2", "label": "未来新增项目", "value": null, "sheet": "Sheet1", "cell": "B3" }
  ]
}
```

`id` 在本次文档中唯一，供风险证据引用；不是跨文件稳定的业务编码。`schemaVersion` 描述协议结构，不随租房项目增减而改变。

当前没有持久化。后端在请求中处理文件，解析器临时文件在处理结束后清理；前端只在内存中保留本次导入，清空或刷新后移除，不写入浏览器本地存储。

后续接 MySQL 时，建议普通列保存 ID、文件名、创建时间等元数据，`JSON` 列保存文档快照。分析结果单独记录，并关联文档与 skill 版本。同一份表可以重复分析。需要按月租等字段高效筛选时，再增加规范化列或生成列索引；当前没有添加建表脚本或数据库依赖。

Agent 的接入点是 `internal/analysis.Analyzer`，接收完整 `Document`，返回摘要、风险项、依据字段 ID 和待确认信息。当前实现返回 `ErrNotConfigured`。后续在这里接入《租房组成判断.md》及模型，不需要改变上传和预览逻辑。Excel 内容应作为待分析数据，不应被当作 Agent 指令执行。

## HTTP 接口

| 接口 | 请求 | 当前行为 |
| --- | --- | --- |
| `GET /api/health` | 无 | 返回服务状态 |
| `GET /api/template` | 无 | 下载仓库中的空白模板 |
| `POST /api/import` | `multipart/form-data`，单个文件字段 `file` | 返回 `{ document, warnings }` |
| `POST /api/analyze` | 上述 `Document` JSON | 校验文档，返回 HTTP 501 和 `analysis_not_configured` |

错误格式为 `{ "error": { "code": "...", "message": "中文说明" } }`。分析接口已定义成功返回结构，但生产实现没有虚构的分析结果。测试中的分析结果只用于验证接口和展示组件。

## 空白模板

一套房填写一份，发给中介确认房源地点、租房费用和联系人信息。

**[下载 Excel 空白模板](outputs/01a11ae7-a608-7692-9440-5edb4b06cfa9/租房信息模板.xlsx)**

在 GitHub 文件页面点击下载按钮，再用 Excel 打开。模板只有一张工作表，左列为项目，右侧“数值”列由中介填写。

## 填写内容

| 项目 | 填写说明 |
| --- | --- |
| 小区/地点 | 填写小区名称或房源所在地，便于区分不同房源 |
| 房租多少钱一个月 | 填写每月房租金额 |
| 押几付几 | 例如“押一付三” |
| 中介费多少 | 填写租客实际承担的中介费 |
| 水费电费多少 | 分别写清水费、电费单价及单位 |
| 物业费多少 | 填写金额与收费周期；包含在租金中时注明 |
| 燃气费 | 填写单价及单位；不适用时注明 |
| 首月总共要付多少 | 请中介核算首期租金、押金、中介费及其他首月应付款，并确认是否包含已付款 |
| 中介姓名 | 填写该房源的对接中介姓名 |

## 怎么使用

1. 每次看房另存一份，建议命名为 `日期-小区-房号.xlsx`。
2. 请中介在右侧“数值”列填写对应信息。没有收费填 `0`，未确定的项目写“待确认”。
3. 这是一份手动填写表，不含自动计算公式。首月总额需要中介核算并填写。
4. 签约前将各项费用与合同核对，特别确认押几付几、水电收费标准和额外收费。

## 可直接发给中介的话

> 麻烦填写这份房源信息表，先写明小区或地点，再写清月租、押几付几、中介费、水电、物业和燃气收费，以及首月总共要付多少。没有的收费填 0，没确认的写“待确认”，最后留下对接中介姓名，谢谢。
