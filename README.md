# 租房信息检查

Go + TypeScript 的最小 Web 应用：上传填写好的 Excel，核对解析内容，登录 Codex，点击“发送并分析”查看回复。

通过官方 Codex App Server 提供 ChatGPT OAuth / API Key 登录。每次分析显式加载仓库内的 [租房费用审查 skill](skills/rental-review/SKILL.md)，联网对比表内租金及收费，并根据 Excel 项目名的加粗标记选择核算目标，显示计算明细、差额和来源链接。可选启用独立的 AI 业务提取链路，将结构化房源和费用记录存入 MySQL，详见 [后台持久化配置](docs/persistence.md)。

MySQL 凭据填写在本机 `.env` 中：复制 `.env.example` 后修改连接串，服务和迁移命令会自动加载。系统环境变量优先；`.env` 已被 Git 忽略，示例文件只保留占位值。

## 启动应用

需要 Go 1.25+、Node.js 22.12+ 和 Codex CLI。本轮真实协议检查使用 `codex-cli 0.153.4`；App Server 协议会随 CLI 版本变化，其他版本需验证兼容性。在仓库根目录执行：

```sh
npm install -g @openai/codex@0.153.4
npm --prefix web ci
npm --prefix web run build
go run ./cmd/server
```

打开 <http://127.0.0.1:8080>。Go 同时提供 API 与构建后的前端，不需要另装 Web 服务器。

1. 在页面选择 **OAuth 登录（ChatGPT）**，点击返回的“打开授权页面”，在官方页面完成授权；页面会自动更新状态。也可以展开 **API Key / 自定义供应商**：只填 Key 可使用 OpenAI，使用其他供应商时填写 API 基础地址、模型和 Key；还可点击 **从 CC Switch 导入并连接**。
2. 在 Excel 中将需要核算的 A 列项目名整体加粗，保存并上传。页面会显示加粗项目及“需核算”标记；可展开“查看将发送的完整内容”，查看实际发送的 JSON。
3. 点击 **发送并分析**。Go 校验后将请求体完整作为 Codex 用户消息，等待最终回复；最长等待 5 分钟，可取消。新文件或刷新会清空页面内容。

OAuth 的本地回调要求浏览器和 Go 服务运行在同一台机器。当前为本机单用户应用，同一服务的浏览器标签页共用 Codex 登录状态；仅允许 localhost / loopback 地址，不提供远程或多用户部署。

登录凭据保存于本应用独立的配置目录，默认是系统用户配置目录下的 `house-rent-table/codex`（Windows：`%APPDATA%/house-rent-table/codex`）。OAuth 和默认 OpenAI Key 由 Codex 管理；自定义供应商的地址、模型、密钥和来源保存为本应用的 `rental-provider.json`，通过临时文件替换写入，Unix 文件权限为 `0600`。浏览器不写入 localStorage/sessionStorage，API Key 提交后立即清空输入，服务响应不返回密钥。子进程通过专用环境变量获取自定义 Key，进程参数中不含 Key，也不继承宿主的 `CODEX_*` / `OPENAI_*` 凭据变量。退出登录会清除本应用保存的供应商 Key。该目录包含凭据，不应提交到 Git。

### 从 CC Switch 导入

先在 CC Switch 的 Codex 页面启用目标供应商，然后展开本页面的 **API Key / 自定义供应商**，点击 **从 CC Switch 导入并连接**。读取的是 CC Switch 写出的生效配置 `config.toml` 和需要时的 `auth.json`；默认读取 `~/.codex`，也识别 `~/.cc-switch/settings.json` 的 `codexConfigDir`。如果使用自定义目录或仅将目录设置保存在新版 CC Switch 数据库中，请展开 **指定配置目录（可选）**，填写包含这两个文件的绝对目录，也支持 `~/...`。

- 导入当前 `model_provider` 对应的地址、模型和 Key，支持 `auth.json` 的 `OPENAI_API_KEY`、供应商内的 `experimental_bearer_token` 和 `env_key`；环境变量需要在启动 Go 服务前设置。配置使用 `profile` 时按对应档案选择模型和供应商。
- 本应用保存独立快照，重启应用后仍可使用；CC Switch 中切换供应商后，在本页面点击 **切换连接** 并重新导入。导入不会复制 OAuth token、MCP、命令或其他工具设置，也不会修改源文件。配置无效或新 app server 启动失败时保留原连接；分析进行中不能切换连接。
- 接入的地址应提供 Responses API。若供应商需要格式转换，应先在 CC Switch 开启本地路由后导入，并保持 CC Switch 运行。当前不直接导入额外 `http_headers`、`env_http_headers` 或 `query_params`，这类配置会提示通过本地路由接入。租房完整分析还需要供应商支持流式回复、联网搜索和计算工具调用。
- 仅有 ChatGPT OAuth 的配置会提示使用本页面的 OAuth 登录，不会转移其登录 token。切回 OAuth 时清除本应用的自定义供应商路由。

可用 `-codex-bin` 指定原生 Codex 可执行文件，`-codex-home` 指定本应用专用配置目录，`-codex-model` 指定账号可用的模型；页面填写或从 CC Switch 导入的模型优先于 `-codex-model`。未指定模型时使用该 Codex 版本的默认模型。请勿将本应用的 `-codex-home` 指向 CC Switch 的源配置目录。Windows 会自动识别标准 npm 安装的原生程序，其他安装布局可显式指定 `codex.exe`。连接成功代表本地配置加载完成，额度、网络和模型访问权限仍需由真实分析请求验证。

可用 `-rent-premium-tolerance 20` 调整租金溢价提示的容忍百分比（默认 20，允许 0 至 100）。这是产品提示规则，不是市场或法律标准；只有样本可比且证据充分时才应用。该容忍值不用于首次付款的算术差额。联网分析最多等待 5 分钟，可随时取消。

Windows 运行需要 Windows 10 或更新版本。Go 服务创建 Codex 时，通过 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 将其直接加入启用了 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的 Job Object；Job 句柄仅由 Go 服务持有，不传给子进程。即使 Go 服务被强制结束、没有执行退出回调，Windows 也会关闭句柄并终止 Job 内的 Codex 及其后代进程。正常关闭时先关闭标准输入，最多等待 1 秒，再关闭 Job；Codex 自行退出时也会清理残留后代。无法绑定 Job 时启动失败，不回退为脱离管理的进程。这里的父进程指实际运行服务的进程；使用 `go run` 时，仅结束外层 `go` 编译启动器不等于结束服务。其他平台保留原有进程关闭方式；当前没有空闲超时或独立守护服务。

接入依据：[官方 Codex App Server 的登录与会话协议](https://learn.chatgpt.com/docs/app-server)、[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 租房审查规则

- 只审查表内已有项目及其关联信息，不额外生成通用租房审查清单。缺少地点、面积或出租方式时，说明对应比较的限制。
- 只有 `bold: true` 的项目是重新计算并与填写值比较的目标。加粗选择的是结果，例如首月总付款；计算时仍可引用未加粗的月租、押付方式等依据。新增、改名或重排目标无需修改代码，多个目标分别核算；没有加粗目标时只核价和检查收费矛盾，不自动计算首月/每月付款。
- 实时查询近期同小区、相近面积/户型、相同出租方式的可比房源，区分挂牌和成交、去除重复房源。优先取得至少 3 个独立样本，报告数量、范围和中位数；样本不足或条件不匹配时降低结论强度，不编造“小区均价”。
- 物业费、水电等优先采用收费公示、物业及公共事业单位来源，核对日期、适用对象、单位和月/季/年周期。只用核价需要的小区、区域和费用项目搜索，不将联系人、电话或整份表格作为搜索词。
- Codex 解释动态字段与收费条件，Go 的 `rental_calculate` 工具使用有理数执行四则运算，返回精确值、八位小数和两位小数。工具不解析收费语义；模型仍需确认单位、抵扣和付款周期。注册工具使用 App Server 的实验协议，已通过本机 `0.153.4` 的会话创建检查，升级 CLI 时需重新验证。
- 当加粗目标表达首次付款含义时，包括押金、首期预付租金及首次应付费用，减去明确抵扣。汇总字段不重复加入；年费按实际首次付款周期计入；未给用量或付款时间的项目不按零处理。加粗目标表达后续月费时，区分月均成本与实际季付/年付现金支出。空白目标可计算已有依据支持的部分，但不能比较填写差额；无法识别算法或非数值项目说明无法核算。
- 每条判断列出 Excel 原文、字段 ID、单元格、计算前提及来源。报告区分明显异常、偏高待确认、未见明显异常、未能核实；来源冲突、过旧、访问失败和缺失不能当作合理依据。

`SKILL.md` 随 Go 二进制内嵌，启动 Codex 时安装到本应用工作目录的 `.agents/skills/rental-review/SKILL.md`。`turn/start` 使用显式 skill 输入；原始 Excel JSON 作为独立文本逐字传递。编辑仓库中的 skill 后需要重新构建并重启后端；运行目录的副本会在下次启动 Codex 时更新。当前不开放网页编辑规则。可选后台提取使用独立版本的规则和 JSON Schema，不加载主分析 skill。

开发时，在仓库根目录执行下面的命令，即可在同一个终端启动前后端（需已安装 GNU Make）：

```sh
make dev-gui
```

命令会在缺少前端依赖时自动执行 `npm --prefix web ci`，编译并启动 Go 后端，再启动支持热更新的前端。打开 <http://127.0.0.1:5173>；按 `Ctrl+C` 同时停止前后端。任一服务退出时，另一服务也会停止；8080 或 5173 端口已占用时会提示先停止已有服务。修改 Go 代码后需重新运行该命令。

也可以使用两个终端分别运行：

```sh
# 终端一：后端
go run ./cmd/server

# 终端二：前端热更新
npm --prefix web run dev
```

打开 <http://127.0.0.1:5173>，开发服务器把 `/api` 请求代理到 Go 的 8080 端口。可通过 `-addr`、`-web-dir`、`-template` 参数调整本机地址、前端目录和模板文件。

## 表格格式

- 一个文件对应一套房源，使用一张有内容的工作表；额外的空工作表允许保留。
- A 列是项目名，B 列是填写内容。首个非空行的 B 列为“数值”时，该行作为表头，A 列可以留空、写“项目”或任意填写说明，例如“详细填写，不要含糊”。也兼容“项目 / 内容”等原有表头。
- 表头只在首个非空行识别，后续同名内容按业务数据保留。无表头文件如果第一项的填写值恰好是“数值”，请先加一行表头，避免与表头标记混淆。
- 项目名称、数量及顺序可以变化。新增、删除、改名、重排不需要修改 Go 结构体或 TypeScript 类型。
- A 列项目名的加粗格式映射为字段的 `bold: true/false`，无论 B 列为空或为零都会保留。表头不作为业务字段，仅加粗 B 列不会选中目标。支持普通单元格、行/列字体及完整加粗的富文本；项目名部分文字加粗时提示统一格式后再上传。条件格式产生的动态外观不作为计算标记，请直接将整个项目名加粗。
- 有名称但未填写的项目保留为 `null`；数字零保留为文本 `"0"`，不是空白。
- 重复名称按原来的顺序分别保留，并显示核对提示。字段保留工作表和单元格位置。
- 金额、单位、押付方式、备注按 Excel 显示文本保留，不猜测、不自动转换金额。原文中的换行也会保留。
- 公式需要先确认结果并粘贴为数值；当前不会重算公式，也不会把可能过期的缓存结果当作有效数据。
- 合并单元格、多张有内容的工作表、B 列之后还有数据、只有值没有项目名称时，明确提示整理格式，不静默丢弃内容。

上传限制：`.xlsx`、最大 10 MB、最多 10 张工作表、每张最多 2000 行、最多 500 个项目。解压总量限制为 32 MB；字段名最多 256 字符，填写值最多 10000 字符。布局改变需要扩展解析规则，单纯增减项目无需改代码。

## 数据协议与后续扩展

业务项目存放在动态数组 `fields` 中。Go 的 `document.Field` 和 TypeScript 的 `RentalField` 只描述一个通用字段，不为房租、停车费等分别声明属性。

以下是示意数据，上传后会使用实际内容：

```json
{
  "schemaVersion": 1,
  "fileName": "房源.xlsx",
  "fields": [
    { "id": "field-1", "label": "月租", "bold": false, "value": "2800元/月", "sheet": "Sheet1", "cell": "B2" },
    { "id": "field-2", "label": "首月总共要付多少", "bold": true, "value": null, "sheet": "Sheet1", "cell": "B3" }
  ]
}
```

`id` 在本次文档中唯一，供风险证据引用；不是跨文件稳定的业务编码。`schemaVersion` 描述协议结构，不随租房项目增减而改变。

`bold` 来自同一行 A 列的项目名，`cell` 仍指向 B 列填写值。导入接口始终返回明确的布尔值；这是 `schemaVersion: 1` 的新增可选属性，旧请求未提供时按未标记处理，不根据字段名称补标记。请求原文中的 true/false 直接传给 Codex；旧页面或旧解析数据需要重新上传才能获得 Excel 格式标记。以后保存 JSON 文档快照时一起保存 `bold`，不必为每个新增核算目标增加数据库列。

后端在请求中处理文件，解析器临时文件在处理结束后清理；前端只在内存中保留本次导入和回复，清空或刷新后移除。点击发送后，数据交由 Codex/所配置的供应商处理。每次分析使用独立的 `ephemeral` 会话，关闭 Codex 命令历史保存；Codex 自身仍会管理登录凭据及运行所需配置和缓存。设置 `RENT_MYSQL_DSN` 后，还会将有效分析请求保存为本地持久化任务，独立调用 AI 提取业务字段并写入 MySQL；刷新、清空、取消主分析不会撤销已经入队的任务或删除历史。只上传 Excel 不入队。

MySQL 使用任务表、房源业务快照表和费用明细表；地点、面积、朝向、押付规则、金额、单位和周期均有明确业务列，JSON 辅助保留原文和证据。标准对象经 Schema 与业务组合校验后入库，费用用 DECIMAL 存储。待写任务和已校验结果先在本地落盘，数据库恢复后按任务 ID 幂等补写，不重复调用 AI。当前不保存主分析报告，也不提供历史列表界面。字段定义、迁移和环境变量见 [持久化说明](docs/persistence.md)。

检查结果下的“坑人”按钮会读取本次表格的“中介姓名”，将反馈直接保存到 MySQL 的 `rental_broker_feedback`（坑人记录表）：新姓名的 `feedback_count` 为 1，已有姓名每次反馈加 1。姓名去除首尾空白后精确匹配，同名中介合并累计；不同姓名分别计数。保存成功才显示累计次数，请求期间禁用按钮；缺少姓名、存在多个不同姓名或数据库不可用时显示原因。此操作不依赖后台 AI 提取完成。已使用 V1 数据库的环境需重新运行 `go run ./cmd/migrate`，再重启服务以启用接口。

Agent 的接入点是 `internal/analysis.Analyzer`：接收校验过的原始 JSON 请求体，返回 `{ "text": "Codex 的最终回复" }`。`internal/codex` 使用 stdio JSON-RPC 管理官方 `codex app-server`，通过 `thread/start` 和 `turn/start` 发起分析。分析指引通过独立的 `developerInstructions` 传递，不拼入用户数据。保留字段顺序、重复名称、空值、换行和来源，既不归一化金额，也不摘要或截断数据；超出限制则明确报错。

只有 `turn/completed` 的状态为 `completed` 时才返回成功，失败或中断不会将部分回复当作分析结论。页面呈现 Markdown 表格和 HTTP(S) 来源链接，禁用模型输出中的 HTML 和图片，并可展开查看逐字保留的回复原文。更换文件、刷新和取消会中止旧请求，后端通知 Codex 中断；一次只允许一项分析或登录变更，避免分析过程中切换账号。

Codex 在独立工作目录、只读沙箱下运行，开启 `web_search="live"`，提供有界的本地金额计算工具，关闭 shell 和多 Agent 功能，拒绝其他工具请求。搜索和计算不改变 Excel 动态字段协议。新增收费项目不需要新增 Go/TypeScript 属性，但新的业务判断规则仍可能需要更新 skill。

## HTTP 接口

| 接口 | 请求 | 当前行为 |
| --- | --- | --- |
| `GET /api/health` | 无 | 返回服务状态 |
| `GET /api/template` | 无 | 下载仓库中的空白模板 |
| `POST /api/import` | `multipart/form-data`，单个文件字段 `file` | 返回 `{ document, warnings }` |
| `GET /api/codex/account` | 无 | 返回登录方式、状态和授权是否等待中，不返回凭据 |
| `POST /api/codex/login` | `{ "type": "chatgpt" }`；或 `{ "type": "apiKey", "apiKey": "...", "baseUrl": "https://example.com/v1", "model": "供应商模型名" }`；或 `{ "type": "apiKey", "source": "ccswitch", "configDir": "可选绝对目录" }` | 发起 OAuth、登记 API Key 或导入 CC Switch 生效配置；默认 OpenAI 可省略地址和模型，导入不能混入手动配置 |
| `POST /api/codex/logout` | 无 | 取消等待中的授权并退出当前登录 |
| `POST /api/analyze` | 上述 `Document` JSON | 原文发送至 Codex，成功返回 `{ "text": "..." }` |
| `POST /api/broker-feedback` | `{ "brokerName": "中介姓名" }` | 按姓名新增或累加坑人反馈，提交成功后返回 `{ "brokerName": "中介姓名", "feedbackCount": 1 }`；姓名为空或超过 256 字符返回 400，数据库未配置或保存无法确认返回 503 |

错误格式为 `{ "error": { "code": "...", "message": "中文说明" } }`。配置或导入无效返回 400，未登录返回 401，忙碌返回 409，Codex 不可用返回 503，超时返回 504，上游失败返回 502。不会将上游可能含凭据的原始错误直接返回浏览器。API 响应禁用缓存，并检查跨来源浏览器请求。

## 空白模板

一套房填写一份，发给中介确认租房费用、小区地点、房间大小、朝向和联系人信息。

**[下载 Excel 空白模板](outputs/01a11ae7-a608-7692-9440-5edb4b06cfa9/租房信息模板.xlsx)**

在 GitHub 文件页面点击下载按钮，再用 Excel 打开。模板只有一张工作表，左列为项目，右侧“数值”列由中介填写。

## 填写内容

| 项目 | 填写说明 |
| --- | --- |
| 房租多少钱一个月 | 填写每月房租金额 |
| 押几付几 | 例如“押一付三” |
| 中介费多少 | 填写租客实际承担的中介费 |
| 水费 | 写清水费单价及单位 |
| 电费 | 写清电费单价及单位 |
| 保洁费 | 填写金额、收费周期及是否必收；没有则填 0 |
| 物业费多少 | 填写金额与收费周期；包含在租金中时注明 |
| 燃气费 | 填写单价及单位；不适用时注明 |
| 首月总共要付多少 | 请中介核算首期租金、押金、中介费及其他首月应付款，并确认是否包含已付款 |
| 以后每个月要付多少钱 | 填写首月之后每月需支付的金额，注明包含哪些固定费用、水电燃气是否另计，以及季付或年付等实际付款周期 |
| 小区地点 | 填写小区名称、所在区域或详细地址，便于区分房源 |
| 房间大小/平方 | 按平方米填写房间面积，可注明约数、使用面积或建筑面积等口径；未确认时写“待确认” |
| 朝向 | 填写房间实际朝向，例如“朝南”“南北通透”；未确认时写“待确认” |
| 中介姓名 | 填写该房源的对接中介姓名 |

“房间大小/平方”和“朝向”依次位于“小区地点”下方，两行均不加粗，默认不作为核算目标；后端仍会将其原文、来源位置和加粗标记传给分析，用于筛选和比较房源。

## 怎么使用

1. 每次看房另存一份，建议命名为 `日期-小区-房号.xlsx`。
2. 请中介在右侧“数值”列填写对应信息。没有收费填 `0`，未确定的项目写“待确认”。
3. 这是一份手动填写表，不含自动计算公式。首月总额和以后每月费用都需要中介核算并填写，后续月费不含押金、中介费等一次性费用。
4. 签约前将各项费用与合同核对，特别确认押几付几、水电收费标准和额外收费。

## 可直接发给中介的话

> 麻烦详细填写这份房源信息表，写清月租、押几付几、中介费，分别填写水费、电费、保洁费、物业费和燃气费的金额、单位或收费周期，以及首月总共要付多少、以后每个月要付多少钱。请注明后续月费包含哪些费用、水电燃气是否另计，以及实际付款周期。没有的收费填 0，没确认的写“待确认”，最后写明小区地点、房间大小（平方米）、朝向和对接中介姓名，谢谢。
