# 租房信息检查

Go + TypeScript 的最小 Web 应用：选择 MiMo、GLM 或 DeepSeek 模型并填写自己的 API Key，上传租房 Excel，核对解析内容后点击“发送并分析”查看回复。

后端通过 HTTP 直连三家固定官方接口，所有模型请求均开启思考模式。每次分析加载仓库内的[租房费用审查规则](skills/rental-review/SKILL.md)，根据 Excel 项目名的加粗标记选择核算目标，显示计算明细和差额；通过供应商搜索服务联网核价。可选启用独立的 AI 业务提取链路，将结构化房源和费用记录存入 MySQL，详见[后台持久化配置](docs/persistence.md)。

MySQL 凭据填写在本机 `.env` 中：复制 `.env.example` 后修改连接串，服务和迁移命令会自动加载。系统环境变量优先；`.env` 已被 Git 忽略，示例文件只保留占位值。

## 启动应用

需要 Go 1.25+、Node.js 22.12+。在仓库根目录执行：

```sh
npm --prefix web ci
npm --prefix web run build
go run ./cmd/server
```

打开 <http://127.0.0.1:8080>。Go 同时提供 API 与构建后的前端。

1. 在 **AI 接口配置** 中选择三种模型之一，填写该供应商的 **API Key**，点击 **验证并保存**。URL、模型 ID 和思考参数均由程序固定。
2. 在 Excel 中将需要核算的 A 列项目名整体加粗，保存并上传。页面显示加粗项目及“需核算”标记；可展开“查看将发送的完整内容”，查看实际发送的 JSON。
3. 点击 **发送并分析**。Go 校验后将请求体完整作为模型用户消息，等待最终回复；最长等待 5 分钟，可取消。新文件或刷新会清空页面中的表格和回复。

### 支持的模型

| 页面选项 | 固定模型 ID | 联网核价 |
| --- | --- | --- |
| MiMo v2.6-Flash | `mimo-v2.6-flash` | 内置 Web Search，需先在小米平台开通插件 |
| GLM 5.3-Flash | `glm-5.3-flash` | 函数工具调用智谱独立 Web Search API |
| DeepSeek Flash | `deepseek-flash` | 函数工具调用 DeepSeek 独立 Search API |

截至 **2026-10-19**，`deepseek-flash` 对应 **DeepSeek V4.1-Flash-1017**；这是官方滚动别名，后续实际版本可能更新。页面会显示这一说明，不再使用已退役模型的旧名称。

三家统一使用官方 **Chat Completions** 接口。思考模式在连接验证、主分析、工具续传和后台提取中均显式开启；GLM 额外保留思考上下文，DeepSeek 使用 `high` 思考强度。供应商的请求、响应、搜索和用量差异由 `internal/aiclient` 处理，上层只读取 `NormalizedResponse`。支持列表由后端提供，连接接口拒绝自定义 URL、模型和思考开关。

搜索与模型请求使用同一家供应商的同一把 Key；搜索可能单独计费。GLM 使用标准 API Key，不使用 Coding Plan 专属地址。没有来源或搜索失败时会显示提示，不将市价当成已核实。MiMo 未开通插件等导致整个模型请求被拒绝时，明确返回分析失败，不静默关闭搜索或切换模型。

后台提取使用三家文档支持的 `json_object` 模式，把 JSON Schema 写进独立系统指令，仍由原有本地 Schema 和业务校验决定能否入库；不会发送未经确认支持的严格 `json_schema` 参数。

保存前发送一次简短模型请求，收到完整、非空回复后才保存。验证不包含表格、不调用搜索或计算工具，最多等待 90 秒，可能产生少量费用。验证失败保留原配置；成功不代表已验证搜索权限或提取质量。修改模型时重新填写 Key；“清除配置”删除本应用保存的供应商选择和密钥。

具体端点、字段映射、官方来源与验证边界见 [三家模型适配说明](docs/model-providers.md)。

配置保存在系统用户配置目录下的 `house-rent-table/api/connection.json`，Windows 为 `%APPDATA%/house-rent-table/api/connection.json`，可用 `-ai-config-dir` 指定其他目录。文件含明文 Key，通过临时文件替换写入，Unix 权限为 `0600`；不要提交到 Git。浏览器不写入 localStorage/sessionStorage，Key 提交后立即清空输入，服务响应不返回密钥。重启后恢复已保存配置；读取状态不会调用模型。

当前为本机单用户应用，仅允许 localhost / loopback 监听地址，同一服务的浏览器标签页共用 API 配置。主分析与配置变更互斥；独立后台提取在每次尝试开始时读取配置快照。

从旧版升级：已移除 Codex CLI/App Server、OAuth 登录及 CC Switch 导入。旧 `/api/codex/*` 路由和 `-codex-bin`、`-codex-home`、`-codex-model` 参数不再可用；启动命令中移除这些参数，在页面选择受支持模型并重新填写 Key。应用不读取或迁移旧版凭据，也不需要安装 Codex。 直接 API 旧版的 `{apiKey, baseUrl, model}` 配置会提示重新连接；不会猜测供应商、自动迁移或转发旧 Key，旧文件在重新保存或清除前保留。

可用 `-rent-premium-tolerance 20` 调整租金溢价提示的容忍百分比（默认 20，允许 0 至 100）。这是产品提示规则，不是市场或法律标准；只有样本可比且证据充分时才应用。该容忍值不用于首次付款的算术差额。

## 租房审查规则

- 只审查表内已有项目及其关联信息，不额外生成通用租房审查清单。缺少地点、面积或出租方式时，说明对应比较的限制。
- 只有 `bold: true` 的项目是重新计算并与填写值比较的目标。加粗选择的是结果，例如首月总付款；计算时仍可引用未加粗的月租、押付方式等依据。新增、改名或重排目标无需修改代码，多个目标分别核算；没有加粗目标时只核价和检查收费矛盾，不自动计算首月/每月付款。
- 接口支持网页搜索时，实时查询近期同小区、相近面积/户型、相同出租方式的可比房源，区分挂牌和成交、去除重复房源。优先取得至少 3 个独立样本，报告数量、范围和中位数；样本不足或条件不匹配时降低结论强度，不编造“小区均价”。
- 物业费、水电等优先采用收费公示、物业及公共事业单位来源，核对日期、适用对象、单位和月/季/年周期。只用核价需要的小区、区域和费用项目搜索，不将联系人、电话或整份表格作为搜索词。
- 模型解释动态字段与收费条件，Go 的 `rental_calculate` 工具使用有理数执行四则运算，返回精确值、八位小数和两位小数。工具不解析收费语义；模型仍需确认单位、抵扣和付款周期。三家均通过函数工具调用同一计算器。
- 当加粗目标表达首次付款含义时，包括押金、首期预付租金及首次应付费用，减去明确抵扣。汇总字段不重复加入；年费按实际首次付款周期计入；未给用量或付款时间的项目不按零处理。加粗目标表达后续月费时，区分月均成本与实际季付/年付现金支出。空白目标可计算已有依据支持的部分，但不能比较填写差额；无法识别算法或非数值项目说明无法核算。
- 报告先给关键结论，核算集中展示费用名称、公式、前提和差额，常见表格正文以 300–500 字为目标。使用中文项目名，只有同名歧义时才附单元格，不显示内部字段 ID；无有效参考的项目合并说明，不生成空对照表。报告区分明显异常、偏高待确认、未见明显异常、未能核实；有效价格对照附可点击来源，来源冲突、过旧、访问失败和缺失不能当作合理依据。

`SKILL.md` 随 Go 二进制内嵌，通过 Chat Completions 的 system 消息单独发送；原始 Excel JSON 作为用户消息逐字传递。编辑规则后需重新构建并重启后端。当前不开放网页编辑规则。可选后台提取使用独立版本的规则和 JSON Schema，不加载主分析规则。

开发时，在仓库根目录执行下面的命令，即可在同一个终端启动前后端（需已安装 GNU Make）：

```sh
make dev-gui
```

命令会在缺少前端依赖时自动执行 `npm --prefix web ci`，编译并启动 Go 后端，再启动支持热更新的前端。打开 <http://127.0.0.1:5173>；按 `Ctrl+C` 同时停止前后端。任一服务退出时，另一服务也会停止；8080 或 5173 端口已占用时会提示先停止已有服务。修改 Go 代码后需重新运行该命令。

也可以使用两个终端分别运行：

```sh
# 终端一：后端
go run ./cmd/server

# 终端二：前端热更新
npm --prefix web run dev
```

打开 <http://127.0.0.1:5173>，开发服务器把 `/api` 请求代理到 Go 的 8080 端口。可通过 `-addr`、`-web-dir`、`-template` 参数调整本机地址、前端目录和模板文件。

## 表格格式

- 一个文件对应一套房源，使用一张有内容的工作表；额外的空工作表允许保留。
- A 列是项目名，B 列是填写内容。首个非空行的 B 列为“数值”时，该行作为表头，A 列可以留空、写“项目”或任意填写说明，例如“详细填写，不要含糊”。也兼容“项目 / 内容”等原有表头。
- 表头只在首个非空行识别，后续同名内容按业务数据保留。无表头文件如果第一项的填写值恰好是“数值”，请先加一行表头，避免与表头标记混淆。
- 项目名称、数量及顺序可以变化。新增、删除、改名、重排不需要修改 Go 结构体或 TypeScript 类型。
- A 列项目名的加粗格式映射为字段的 `bold: true/false`，无论 B 列为空或为零都会保留。表头不作为业务字段，仅加粗 B 列不会选中目标。支持普通单元格、行/列字体及完整加粗的富文本；项目名部分文字加粗时提示统一格式后再上传。条件格式产生的动态外观不作为计算标记，请直接将整个项目名加粗。
- 有名称但未填写的项目保留为 `null`；数字零保留为文本 `"0"`，不是空白。
- 重复名称按原来的顺序分别保留，并显示核对提示。字段保留工作表和单元格位置。
- 金额、单位、押付方式、备注按 Excel 显示文本保留，不猜测、不自动转换金额。原文中的换行也会保留。
- 公式需要先确认结果并粘贴为数值；当前不会重算公式，也不会把可能过期的缓存结果当作有效数据。
- 合并单元格、多张有内容的工作表、B 列之后还有数据、只有值没有项目名称时，明确提示整理格式，不静默丢弃内容。

上传限制：`.xlsx`、最大 10 MB、最多 10 张工作表、每张最多 2000 行、最多 500 个项目。解压总量限制为 32 MB；字段名最多 256 字符，填写值最多 10000 字符。布局改变需要扩展解析规则，单纯增减项目无需改代码。

## 数据协议与后续扩展

业务项目存放在动态数组 `fields` 中。Go 的 `document.Field` 和 TypeScript 的 `RentalField` 只描述一个通用字段，不为房租、停车费等分别声明属性。

以下是示意数据，上传后会使用实际内容：

```json
{
  "schemaVersion": 1,
  "fileName": "房源.xlsx",
  "fields": [
    { "id": "field-1", "label": "月租", "bold": false, "value": "2800元/月", "sheet": "Sheet1", "cell": "B2" },
    { "id": "field-2", "label": "首月总共要付多少", "bold": true, "value": null, "sheet": "Sheet1", "cell": "B3" }
  ]
}
```

`id` 在本次文档中唯一，供风险证据引用；不是跨文件稳定的业务编码。`schemaVersion` 描述协议结构，不随租房项目增减而改变。

`bold` 来自同一行 A 列的项目名，`cell` 仍指向 B 列填写值。导入接口始终返回明确的布尔值；这是 `schemaVersion: 1` 的新增可选属性，旧请求未提供时按未标记处理，不根据字段名称补标记。请求原文中的 true/false 直接传给模型；旧页面或旧解析数据需要重新上传才能获得 Excel 格式标记。以后保存 JSON 文档快照时一起保存 `bold`，不必为每个新增核算目标增加数据库列。

后端在请求中处理文件，解析器临时文件在处理结束后清理；前端只在内存中保留本次导入和回复，清空或刷新后移除。点击发送后，数据交由所配置的模型供应商处理。每次分析使用独立的消息集合；供应商的数据处理规则仍由对应服务决定。设置 `RENT_MYSQL_DSN` 后，还会将有效分析请求保存为本地持久化任务，独立调用 AI 提取业务字段并写入 MySQL；刷新、清空、取消主分析不会撤销已经入队的任务或删除历史。只上传 Excel 不入队。

MySQL 使用任务表、房源业务快照表和费用明细表；地点、面积、朝向、押付规则、金额、单位和周期均有明确业务列，JSON 辅助保留原文和证据。标准对象经 Schema 与业务组合校验后入库，费用用 DECIMAL 存储。待写任务和已校验结果先在本地落盘，数据库恢复后按任务 ID 幂等补写，不重复调用 AI。当前不保存主分析报告，也不提供历史列表界面。字段定义、迁移和环境变量见 [持久化说明](docs/persistence.md)。

检查结果下的“坑人”按钮会读取本次表格的“中介姓名”，将反馈直接保存到 MySQL 的 `rental_broker_feedback`（坑人记录表）：新姓名的 `feedback_count` 为 1，已有姓名每次反馈加 1。姓名去除首尾空白后精确匹配，同名中介合并累计；不同姓名分别计数。保存成功才显示累计次数，请求期间禁用按钮；缺少姓名、存在多个不同姓名或数据库不可用时显示原因。此操作不依赖后台 AI 提取完成。已使用 V1 数据库的环境需重新运行 `go run ./cmd/migrate`，再重启服务以启用接口。

AI 的接入点是 `internal/analysis.Analyzer`：接收校验过的原始 JSON 请求体，返回 `{ "text": "AI 的最终回复" }`，归一化的引用、来源和提示分别通过可选 `citations`、`sources`、`warnings` 数组传递。`internal/aiclient` 直接发送 HTTP 请求，审查规则与用户数据分开传递。保留字段顺序、重复名称、空值、换行和来源，不归一化金额、不摘要或截断数据；超出限制则明确报错。

仅接受正常完成的回复，拒绝失败、截断、拒绝回答、空回复或畸形数据，不将部分输出作为结论。每次最多 16 轮工具交互、每轮最多 64 个函数调用，GLM/DeepSeek 每次分析最多 8 次独立搜索；模型不能调用 shell、读写本地文件或执行任意工具。连续请求完整续传思考字段、函数调用和工具结果，后台提取使用独立请求与超时。HTTP 重定向被拒绝，防止 Key 被转发到其他地址。

页面呈现 Markdown 表格和 HTTP(S) 来源链接，将带位置的引用渲染为可点击编号，没有位置的来源放入检索来源列表；禁用模型输出中的 HTML 和图片，并可展开查看逐字保留的回复原文。更换文件、刷新和取消会中止旧请求，并取消后端对应的 HTTP 请求。新增收费项目不需要新增 Go/TypeScript 属性，但新的业务判断规则仍可能需要更新审查规则。

## HTTP 接口

| 接口 | 请求 | 当前行为 |
| --- | --- | --- |
| `GET /api/health` | 无 | 返回服务状态 |
| `GET /api/template` | 无 | 下载仓库中的空白模板 |
| `POST /api/import` | `multipart/form-data`，单个文件字段 `file` | 返回 `{ document, warnings }` |
| `GET /api/ai/models` | 无 | 返回三种模型的展示信息和能力提示，不返回端点或 Key |
| `GET /api/ai/config` | 无 | 返回 `connected`、`provider`、`name`、`model`；旧配置返回 `needsReconnect: true`，不返回 Key |
| `POST /api/ai/connect` | `{ "provider": "mimo", "apiKey": "..." }` | provider 仅允许 `mimo` / `glm` / `deepseek`，验证成功后保存，返回 `{ "ok": true }` |
| `POST /api/ai/disconnect` | 无 | 清除已保存配置，返回 `{ "ok": true }` |
| `POST /api/analyze` | 上述 `Document` JSON | 原文发送至模型，成功返回 `{ "text": "..." }`；归一化信息通过可选 `citations`、`sources`、`warnings` 数组返回 |
| `POST /api/broker-feedback` | `{ "brokerName": "中介姓名" }` | 按姓名新增或累加坑人反馈，提交成功后返回 `{ "brokerName": "中介姓名", "feedbackCount": 1 }`；姓名为空或超过 256 字符返回 400，数据库未配置或保存无法确认返回 503 |

错误格式为 `{ "error": { "code": "...", "message": "中文说明" } }`。配置或导入无效返回 400，未配置返回 401，忙碌返回 409，配置不可用返回 503，超时返回 504，上游失败返回 502。不会将上游可能含凭据的原始错误直接返回浏览器。API 响应禁用缓存，并检查跨来源浏览器请求。

## 开发检查

```sh
go test ./...
go vet ./...
npm --prefix web run build

# 首次运行浏览器测试前安装 Chromium headless shell
cd web
npx playwright install chromium --only-shell
npm run test:e2e
```

## 空白模板

一套房填写一份，发给中介确认租房费用、小区地点、房间大小、朝向和联系人信息。

**[下载 Excel 空白模板](outputs/01a11ae7-a608-7692-9440-5edb4b06cfa9/租房信息模板.xlsx)**

在 GitHub 文件页面点击下载按钮，再用 Excel 打开。模板只有一张工作表，左列为项目，右侧“数值”列由中介填写。

## 填写内容

| 项目 | 填写说明 |
| --- | --- |
| 租几个月 | 填写总租期，例如“12个月”；与押几付几的付款周期分开填写，未确认时写“待确认” |
| 房租多少钱一个月 | 填写每月房租金额 |
| 押几付几 | 例如“押一付三” |
| 中介费多少 | 填写租客实际承担的中介费 |
| 水费 | 写清水费单价及单位 |
| 电费 | 写清电费单价及单位 |
| 保洁费 | 填写金额、收费周期及是否必收；没有则填 0 |
| 物业费多少 | 填写金额与收费周期；包含在租金中时注明 |
| 燃气费 | 填写单价及单位；不适用时注明 |
| 首月总共要付多少 | 请中介核算首期租金、押金、中介费及其他首月应付款，并确认是否包含已付款 |
| 以后每个月要付多少钱 | 填写首月之后每月需支付的金额，注明包含哪些固定费用、水电燃气是否另计，以及季付或年付等实际付款周期 |
| 小区地点 | 填写小区名称、所在区域或详细地址，便于区分房源 |
| 房间大小/平方 | 按平方米填写房间面积，可注明约数、使用面积或建筑面积等口径；未确认时写“待确认” |
| 朝向 | 填写房间实际朝向，例如“朝南”“南北通透”；未确认时写“待确认” |
| 中介姓名 | 填写该房源的对接中介姓名 |

“房间大小/平方”和“朝向”依次位于“小区地点”下方，两行均不加粗，默认不作为核算目标；后端仍会将其原文、来源位置和加粗标记传给分析，用于筛选和比较房源。

## 怎么使用

1. 每次看房另存一份，建议命名为 `日期-小区-房号.xlsx`。
2. 请中介在右侧“数值”列填写对应信息。没有收费填 `0`，未确定的项目写“待确认”。
3. 这是一份手动填写表，不含自动计算公式。首月总额和以后每月费用都需要中介核算并填写，后续月费不含押金、中介费等一次性费用。
4. 签约前将各项费用与合同核对，特别确认押几付几、水电收费标准和额外收费。

## 可直接发给中介的话

> 麻烦详细填写这份房源信息表，写清租几个月、月租、押几付几、中介费，分别填写水费、电费、保洁费、物业费和燃气费的金额、单位或收费周期，以及首月总共要付多少、以后每个月要付多少钱。请注明后续月费包含哪些费用、水电燃气是否另计，以及实际付款周期。没有的收费填 0，没确认的写“待确认”，最后写明小区地点、房间大小（平方米）、朝向和对接中介姓名，谢谢。

本地使用 Python 3.11 或更新版本运行，无需安装额外依赖：

python .github/scripts/check_template.py
